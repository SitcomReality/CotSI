This is a well-structured and highly thoughtful redesign document. It correctly identifies the root causes of the previous system's artifacts and establishes a clear, physically-motivated pipeline. The shift to data-driven biomes and continuous feature density is a strong architectural improvement.

However, there are several flaws, logical inconsistencies, and architectural bottlenecks in the plan that will cause issues during implementation. Here is a breakdown of the problems grouped by category.

---

### 1. Architectural Conflicts: Chunk-S seamlessness vs. Global Passes

The document states as Design Principle 4: *"Every sample is a pure function of `(seed, q, r)`. Two adjacent chunks produce identical values at their shared hexes without communication."* 
However, several passes fundamentally violate this principle if the game generates chunks on-demand (infinite world) rather than generating the entire map at once.

*   **Water BFS (Pass 7) cannot work on-demand with a local ring:** You state `waterType` is determined by a BFS to see if a body of water connects to the map boundary. You propose a border ring of `maxLookupRadius = 3` to handle this. A BFS depth of 3 is nowhere near enough to determine if a lake connects to the ocean. If chunks are generated independently as the player moves, a local chunk cannot know if a sprawling lake 5 chunks away eventually touches the map edge. This requires either a global pre-pass (breaking infinite generation) or a fundamentally different algorithm (e.g., cell-automa or distance-to-edge fields).
*   **River Tracing (Pass 5) breaks local generation:** Rivers are traced downhill from a source to a waterbody. If a river starts in Chunk A and flows into Chunk B, Chunk B must know about the river to apply the `isRiver` tag and moisture boost. If Chunk B is generated before Chunk A, or if Chunk A's river flows out the right side but Chunk B hasn't generated the left side yet, you get severed rivers. The doc lists "Rivers truncate at generation boundary" as a known limitation, but this is a fatal flaw for infinite/chunked worlds. Rivers will constantly appear and disappear as chunks load/unload.
*   **Supernatural Epicenter "Region Growth" is non-local:** The doc mentions "Epicenter regions grow outward from seed points... producing irregular, contiguous event zones." If this is evaluated purely by a thresholded noise field (as the Phase 0 placeholder suggests), it works as a pure function. But if it requires actual region-growing from a seed point, a chunk cannot know if it falls inside a region without knowing where the seed point is and tracing the path to the current hex.

### 2. Logical Inconsistencies in the Pipeline

*   **Temperature for Infinite Maps defaults to 0.5:** In Section 5, the latitude term is `1.0 - (distFromCenter / radius)`. For an infinite map, `radius` is theoretically infinite, making the term `1.0`. But the code has a fallback: `radius > 0 ? ... : 0.5`. This means in an infinite world, the base latitude temperature is hardcoded to `0.5` everywhere. Combined with `0.15` variation and `-0.40` lapse rate, temperature in infinite worlds will be entirely dictated by elevation, completely breaking hot/cold biomes (tundra, deserts) based on latitude.
*   **Elevation Normalization contradicts the "Pure Function" sampler:** In Section 5, the code for `sampleBaseFields` hardcodes weights: `continent * 0.60 + detail * 0.25 + ridges * 0.15`. The doc notes: *"In phases where ridge noise hasn't been implemented yet, the elevation composite is normalized... Each phase doc specifies its normalization formula."* But if `sampleBaseFields` is a shared pure function, it cannot dynamically know which "phase" the game is currently in. If Phase A calls this function, it will get max elevation 0.85, breaking `mountainThreshold`. The function signature needs to accept weight configurations, or the phase weights must be injected into `noiseConfig`.
*   **Moisture Feedback Loop (Mostly) Eliminated, but Localized One Created:** The doc correctly identifies and kills the macro moisture-water feedback loop. However, Pass 6 `classifyTerrain` still has: `if (elevation < R.waterMaxElevation) { if (moisture > R.waterMinMoisture) return 'water'; }`. Because Pass 3 adds `nearWaterBoost` to moisture based on Provisional Water, a tile that *barely* missed being water in Pass 2 might get pushed over the `waterMinMoisture` threshold by its neighboring water tile, turning it into water in Pass 6. This creates a 1-hex moisture-driven expansion of water bodies. This might be intended, but it is a feedback loop that could cause straight-edged water bodies to become blobby.

### 3. Conceptual & Design Flaws

*   **Mixing Supernatural and Natural Biomes in `BIOME_PRIORITY_ORDER`:** Section 7.1 states: *"Supernatural biomes are listed first (highest priority) but skipped by `selectBiome` since they have no `climateRange`"*. This is a code smell. If a list is explicitly for iterating climate matching, putting items in it that are explicitly meant to be skipped is confusing. Supernatural biomes should live in a separate registry/array (`SUPERNATURAL_BIOMES`) consumed entirely by Pass 4b.
*   **Floating Islands tied purely to Elevation:** The `classifyTerrain` function returns `'floatingIsland'` if `elevation > R.floatingIslandThreshold`. In the Brass Grave supernatural biome example, it says `supportsFloatingIslands: true` because "divine war machines might have floating fragments." But because classification is purely elevation-based, floating islands will only ever appear at the absolute highest noise peaks (0.985+). You will not get floating fragments scattered across a crash site; you will only get them on the highest mountains inside the crash site. If you want floating terrain as an *event* feature, it needs to be placed by epicenter noise, not global elevation noise.
*   **River Termination at Local Minima:** Pass 5 states rivers stop at "a local minimum". If a river hits a local minimum that is *not* a water tile, it just stops. In real terrain, this creates a lake that overflows. In this pipeline, the river will simply vanish into the ground, leaving a dead-end moisture boost in a valley. This will look unnatural.
*   **`feature.density` Schema Contradiction:** Section 4 Output Schema defines `feature: { kind, density? } | null`. The `?` implies density is optional. But Section 10 explicitly states the goal is to move *away* from enums to continuous density. If density is continuous, it should be a required float (e.g., `0.0` to `1.0`) whenever a feature exists, not an optional field hearkening back to the old enum system.

### 4. Minor Issues & Edge Cases

*   **`hexDistance` vs Map Shape:** The shift from `Math.abs(r) / radius` to `hexDistance(q, r, 0, 0) / radius` correctly makes circular climate zones. However, if the playable map area is a rectangle/square (which is common), the corners of the map will now uniformly hit the "cold" extreme (0.0), while the center is hot. This makes square maps have massive frozen corners. If the map is square, an elliptical or L-infinity distance metric might be more aesthetically pleasing.
*   **Slope Normalization Readability:** The formula `totalDiff / (6 * SLOPE_NORMALIZATION)` is mathematically fine, but conceptually confusing. `SLOPE_NORMALIZATION = 0.3` implies you are dividing by 1.8. It would be much clearer to define `AVG_DELTA_95TH = 0.3` and write: `totalDiff / (6 * AVG_DELTA_95TH)`.
*   **Single Biome Mode Backward Compatibility:** Section 15 says single-biome mode "remains supported... all hexes use that biome — no climate-based selection occurs." But because Pass 6 still runs `classifyTerrain` using the biome's `terrainRules`, a single-biome map will still generate water, mountains, and forests based on the global noise. If a user selects "Desert" biome expecting a flat sandy map, they will instead get oceans, peaks, and forests classified *within* the desert archetype's ruleset. You may need an archetype flag like `suppressClimateVariation` if true single-terrain maps are expected.

### Summary of Recommended Fixes

1.  **Separate Global vs. Local Generation:** Explicitly define which passes can be done purely locally (Passes 1-4b, 6, 8) and which require map-wide state (Rivers, Water BFS). For infinite maps, Rivers and Water Type BFS must either be deferred to a chunk-relay/loading system, or approximated using purely local noise (e.g., using downhill vector fields instead of explicit path tracing).
2.  **Fix Infinite Temperature:** Replace the `1.0 - (dist/radius)` with a very-low-frequency temperature noise field for infinite maps, as suggested in the doc, but make it the *primary* driver for infinite maps rather than falling back to `0.5`.
3.  **Inject Phase Weights:** Update `sampleBaseFields` to accept the weightings of continent/detail/ridge as parameters so the pure function can adapt to phase implementations without code branching.
4.  **Decouple Floating Islands from Elevation:** Allow the Epicenter pass to assign structural tags (like `floatingIsland`) independent of the global elevation peak threshold.
5.  **Clean up Biome Lists:** Remove supernatural biomes from `BIOME_PRIORITY_ORDER`.
